# Ameen Website Implementation Brief

## Purpose

This document gives Claude or any web developer a clear implementation brief for building the first public Ameen website.

The website should be built as a professional enterprise SaaS landing website that supports demo requests and design partner pilot conversations.

## Recommended First Version

Version:

> Ameen Website v0.1 - Commercial Pilot Website

Primary audience:

- Saudi CISOs
- CIOs
- Compliance leaders
- Internal audit teams
- Consulting partners
- Procurement stakeholders

Primary objective:

> Generate qualified demo and pilot conversations.

## Required Pages

### 1. Home

Path:

`/`

Purpose:

Explain Ameen quickly and drive demo requests.

Must include:

- Hero
- Problem
- Simple workflow
- Product capabilities
- Trust pillars
- Framework overview
- Pilot CTA
- FAQ

### 2. Product

Path:

`/product`

Purpose:

Explain how Ameen works.

Must include:

- Document upload
- AI classification
- Control mapping
- Human review
- Evidence management
- Readiness dashboard
- Reporting

### 3. AI & Trust

Path:

`/ai-trust`

Purpose:

Address AI, privacy, evidence, and trust concerns.

Must include:

- Explainable AI
- Human approval
- Local analyzer option
- Customer-controlled deployment
- Data handling
- Legal boundaries

### 4. Saudi Frameworks

Path:

`/frameworks`

Purpose:

Show supported and planned compliance frameworks honestly.

Must include:

- ECC
- CCC
- TCC
- OSMACC
- DGA/Qiyas planned
- PDPL planned
- Clear status labels

### 5. Government Solution

Path:

`/solutions/government`

Purpose:

Speak to government and public-sector organizations.

Must include:

- Customer-controlled deployment
- Local analyzer
- Arabic-first readiness
- Evidence traceability
- Pilot model

### 6. Consultants Solution

Path:

`/solutions/consultants`

Purpose:

Show how consulting firms can use Ameen to scale assessments.

Must include:

- Faster document review
- Standardized readiness outputs
- Multi-client deployment model
- Consultant-managed pilot option

### 7. Pilot Program

Path:

`/pilot`

Purpose:

Convert interested buyers to a controlled pilot.

Must include:

### 8. About

`/about`

Purpose:

Build company trust.

Must include:

### 9. Contact

Path:

`/contact`

Purpose:

Capture leads.

Must include:

- Request demo form
- Pilot interest form
- Basic qualification questions

## Required Forms

### Demo Request Form

Fields:

- Name
- Work email
- Organization
- Job title
- Phone optional
- Sector
- Primary compliance interest
- Message

### Pilot Interest Form

Additional fields:

- Preferred deployment model
- Target framework
- Number of documents expected
- Pilot timeline
- Whether data is regulated/sensitive

## Technical Requirements

The first version should be simple and reliable.

Recommended stack:

- Static website or lightweight web app
- No unnecessary backend unless needed
- Contact form can initially use a simple email/form provider or GitHub issue capture depending deployment choice
- Responsive mobile-first design
- Fast page loading
- SEO metadata
- Arabic-ready structure

## Content Requirements

Use content from the Ameen Operating System documents:

- Homepage copy
- Product page
- AI & Trust page
- Frameworks page
- Government solution
- Consultants solution
- Pilot program
- Legal disclaimer

Do not invent new positioning that conflicts with AOS.

## Compliance Claim Requirements

Every page must follow these rules:

Use:

- Readiness assessment
- Alignment support
- Evidence guidance
- Human-reviewed output
- Explainable mapping

Do not use:

- Certified by NCA
- Guaranteed compliance
- Audit pass guarantee
- Regulator-approved
- Replaces auditor

## Conversion Requirements

Each page should have one primary CTA:

> Request Demo

Pilot-related pages may use:

> Apply for Design Partner Pilot

## SEO Requirements

Initial keyword themes:

- Saudi compliance readiness platform
- NCA ECC readiness
- AI compliance Saudi Arabia
- Cybersecurity compliance assessment Saudi
- Evidence-based compliance readiness
- Saudi GRC AI platform

## Analytics Requirements

Track:

- Demo request clicks
- Pilot request clicks
- Form submissions
- Page visits
- Framework page visits
- AI Trust page visits

## Accessibility Requirements

Minimum:

- Clear contrast
- Keyboard navigation
- Semantic headings
- Descriptive buttons
- No text embedded only in images
- Mobile readability

## Security Requirements

Do not expose:

- API keys
- customer files
- internal framework drafts
- private product screenshots containing real data
- unreviewed legal claims

## Launch Checklist

Before publishing:

- All claims reviewed against AOS legal disclaimer
- Framework statuses accurate
- Contact form tested
- Mobile layout tested
- Broken links checked
- Demo CTA visible on every page
- No customer names unless approved
- No regulator endorsement claim

## Final Implementation Instruction

Build the website as a trust-building sales asset, not as a hype page.

The website should make Ameen look ready for controlled pilots, not claim full enterprise market maturity before legal, security, and review gates are closed.
